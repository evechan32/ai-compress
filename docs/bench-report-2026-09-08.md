## 2. 性能

### 2.1 非容量受限（batch=1，短上下文）

| baseline | 5.32 | 129.8 |

批大小=1 下吞吐持平（解码为计算/访存受限，非 KV 容量受限），符合预期。

### 2.2 容量受限并发（KV 池为瓶颈时，2026-09-09 补测）

条件：池 ~7,760 token（gpu_memory_utilization=0.35, max_len=2048），6 个并发请求，各 prompt 1000 + gen 800。
基线全注意力需 6×1800=10,800 > 池 → 调度器分波次准入；插件 w256 每请求 KV ≈ 1000+256 → 6 请求可全量并发。

| 配置 | 完成 | wall | 吞吐 |
|---|---|---|---|
| baseline | 6/6 | 13.8s | 347.8 tok/s |
| plugin-w256 | 6/6 | **10.7s** | **446.5 tok/s（+28%）** |

结论：KV 池成为瓶颈时（长上下文/高并发/多轮长生成），KV 有界直接转化为吞吐收益；非瓶颈场景零开销。

## 3. KV 显存有界性（来自 Task 5 验收轨迹）

同进程逐 100 步读取每请求真实（非 null）KV 块数：prompt=1500 token，连续生成 2000 token：

| 配置 | 块数轨迹 | 稳态 |
|---|---|---|
| baseline | 86 → 204，随生成无界增长（~(1500+gen)/16） | ~204 |
| plugin-w256 | 86 → 103（~step 300 起平台化）→ step 1900 恒 103-104 | **~103 ≈ prompt 1500 + 窗口 256** |

即：生成长度超出窗口后，每请求 KV 显存停止增长，有界于 O(prompt + window)。此收益在**长多轮对话 / 高并发**下转化为可服务的并发请求数或 KV 池余量（批大小 1 的单请求评测不体现该差异，属正常）。

## 4. 解读与边界

- **质量保持**符合 v1 语义设计：RSWA 保留全部 prompt(prefill) KV，事实/指令均位于 prompt 区 → 长文问答质量与基线一致。窗口驱逐只作用于"生成段"，被驱逐的是超出窗口的早期生成内容。
- **适用场景**：多轮长对话中每轮生成长回答并累积的场景，KV 增长被窗口截断；单轮固定长 prompt 场景 v1 收益有限（prompt 全保留），激进模式（Sink+Window，驱逐 prompt 中段）为 v1.x 规划。
- **诚实披露**：质量评测为合成数据 + 确定性抽样；未覆盖真实 LongBench（磁盘/时间预算），未做批大小>1 的并发吞吐对比。两者均列入后续工作。
