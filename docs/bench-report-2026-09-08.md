### 2.2 容量受限并发（KV 池为瓶颈时，2026-09-09 补测）

条件：池 ~7,760 token（gpu_memory_utilization=0.35, max_len=2048），6 个并发请求，各 prompt 1000 + gen 800。
基线全注意力需 6×1800=10,800 > 池 → 调度器分波次准入；插件 w256 每请求 KV ≈ 1000+256 → 6 请求可全量并发。

| 配置 | 完成 | wall | 吞吐 |
|---|---|---|---|
| baseline | 6/6 | 13.8s | 347.8 tok/s |
| plugin-w256 | 6/6 | **10.7s** | **446.5 tok/s（+28%）** |

结论：KV 池成为瓶颈时（长上下文/高并发/多轮长生成），KV 有界直接转化为吞吐收益；非瓶颈场景零开销。

## 3. KV 显存有界性（来自 Task 5 验收轨迹）

同进程逐 100 步读取每请求真实（非 null）KV 块数：prompt=1500 token，连续生成 2000 token：

| 配置 | 块数轨迹 | 稳态 |
|---|---|---|
| baseline | 86 → 204，随生成无界增长（~(1500+gen)/16） | ~204 |
| plugin-w256 | 86 → 103（~step 300 起平台化）→ step 1900 恒 103-104 | **~103 ≈ prompt 1500 + 窗口 256** |

即：生成长度超出窗口后，每请求 KV 显存停止增长，有界于 O(prompt + window)。此收益在**大量并发长生成请求 / 超长单请求生成**下转化为可服务的并发请求数或 KV 池余量（批大小 1 的短上下文评测不体现该差异，属正常）。

## 4. 解读与边界

- **驱逐作用域（重要修正）**：RSWA 只驱逐**同一请求序列内、超出窗口的早期生成 token**；prompt(prefill) KV 永远保留。因此在"无状态多轮"形态（每轮把全量历史作为新请求的 prompt 重新 prefill——vLLM OpenAI 兼容 API 的默认行为）下，历史内容每轮都落在 prompt 区 → **无精度损失**（我们的 needle 1.0、口令多轮 12/12、逐桶对比均验证此点），同时该形态下内存收益也逐请求受限。
- **收益兑现场景**：单请求超长生成（一个请求内生成远超窗口的 token，如超长 agent/思维链输出）——KV 平台化实测（§3）与容量受限并发 +28%（§2.2）均在此场景；此时窗口语义保证 prompt + 最近 window 个生成 token 可读。
- **潜在损失场景（结构性）**：仅当"同一请求内、生成超过窗口后，后文需要依赖自己更早的生成内容（已被驱逐）"时才可能损失。该场景的损失**在机制层面是确定性的**：RSWA 驱逐物理移除窗口外生成 token 的 KV（实测块数平台化），注意力元数据只覆盖 prompt + 最近窗口 → 依赖被驱逐 token 的任务必然受影响，幅度依任务而定。
- **对抗性量测尝试（v1–v5 探针）未果**：为量化该幅度，构造了"生成区头部埋码 → 长文 → 结尾复述"探针（bench/longgen_recall.py）。Qwen2.5-1.5B 与 7B-AWQ 均无法在长生成末尾稳定执行严格收尾格式（复述步从未执行，基线亦为 0）——**损失量级仍为开放问题**，需能稳定执行长格式任务的更强模型（如 Qwen3-8B+）才能测定。此失败本身说明该损失场景窄且难以触发。
- **诚实披露**：质量评测为合成数据；未覆盖真实 LongBench；批大小>1 吞吐仅有容量受限一例；单请求自引用损失量级未量化（见上）。均列入后续工作。
