# 三种 query-agnostic 打分信号的注意力热点（实测）

> 脚本：`bench/attn_signal_heatmap.py`｜图：`docs/figs/attn-signal/`｜2026-09
> 设置：Qwen2.5-1.5B，**最后一层**（layer 27），context 484 token，needle（`K7XQ21`）
> 放在第 **237** 位。三种信号都归一化成"每个位置的重要性"。

## 三种信号是什么

| 信号 | query 从哪来 | 语义 |
|---|---|---|
| **LM** | 模型自己的 Q（prefill 的因果注意力） | 语言建模"平时看谁" |
| **KVzip** | "请复述上文"探针（带 cache 跑一遍，读注意力） | 重建"需要谁" |
| **K-as-Q** | K 自己（`softmax(K Kᵀ/√d)`） | 自相似"谁冗余/中心" |

## 结论

1. **复述 vs baseline(LM)：+0.62 正相关，但 top-k 完全不同。**
   相关只来自"两者都含 sink"；LM 的 top-10 **全在开头 47 位**，复述的 top-10 **含 needle 一簇**。

2. **复述 vs K-as-Q：−0.53 负相关**——两个信号在"选谁"上**系统性相反**。
   自相似奖励冗余/中心，复述奖励信息/离群，方向反了。

3. **‖V‖（value 范数）几乎是平的**（top10% 只占 15.2%，needle rank 171），
   和谁都不太相关 → **单独不能当重要性信号**。KVzip 只把它当**乘子**：
   `kvzip·‖V‖` 与 `kvzip` 相关 +0.74、needle rank 仍是 6，**排序基本不变**（只微调）。
   → 这解释了为什么 KVzip 把它放在最后一步做 rescale，而不是打分本身。

4. **三者的"总量分布"看起来接近（熵 0.85–0.96），差别全在 top-k 打在哪。**

## 对我们的意义

- 我们的 `PE_SCORE_MODE=context`（采样 prompt query + max）≈ **LM 那一行**，所以它在
  needle 类任务上会漏掉信息 token（needle rank 98）。
- 这解释了为什么 LongBench F1 上 context 够用（答案不依赖单点），但**在 retrieval/needle
  类高压缩比任务上，KVzip 式重建应该明显更好**——这一项我们还没测（TODO）。
- `expected`（ExpectedAttention）≈ 用 query 分布估计，也在 LM 这一族里，所以它没优势。
