# 三种 query-agnostic 打分信号的注意力热点（实测）

> 脚本：`bench/attn_signal_heatmap.py`｜图：`docs/figs/attn-signal/`｜2026-09
> 设置：Qwen2.5-1.5B，**最后一层**（layer 27），context 484 token，needle（`K7XQ21`）
> 放在第 **237** 位。三种信号都归一化成"每个位置的重要性"。

## 三种信号是什么

| 信号 | query 从哪来 | 语义 |
|---|---|---|
| **LM** | 模型自己的 Q（prefill 的因果注意力） | 语言建模"平时看谁" |
| **KVzip** | "请复述上文"探针（带 cache 跑一遍，读注意力） | 重建"需要谁" |
| **K-as-Q** | K 自己（`softmax(K Kᵀ/√d)`） | 自相似"谁冗余/中心" |

## 结果

| 信号 | top-10 位置 | needle rank | needle 占比 | 归一化熵 |
|---|---|---|---|---|
| **LM** | `0,4,6,8,11,12,20,23,35,47` | **98/484** | 0.195% | 0.845 |
| **KVzip** | `0,2,5,11,`**`229,232,233,234,237,242`** | **6/484** | **1.910%** | 0.873 |
| **K-as-Q** | `297,309,313,319,320,321,325,369,381,405` | **431/484** | 0.034% | 0.907 |

（needle 在第 237 位）

## 三个结论（直接可视/可数）

1. **LM 的 top-10 全在开头 47 个位置**——注意力被 **sink 主导**；真正的信息 token（needle，第 237 位）只排第 **98**。
   → "平时被看" ≈ "sink + 局部"，**不是信息价值**。

2. **KVzip 的 top-10 里有一簇紧贴 needle：`229,232,233,234,237,242`**——复述探针**精确锁定了 needle**（rank **6**，占比 0.195% → **1.910%，差 10 倍**）。
   → 这就是"造一个复述探针"为什么有用：它**强制**模型去读需要复现的内容。

3. **K-as-Q 的 top-10 全在 needle 之后（297–405）**，needle 排 **431/484**（接近垫底）。
   → 自相似测的是"**谁中心/冗余**"，不是"谁承载信息"；离群的信息 token 反被惩罚。
   → 这也解释了 kvpress 里 `knorm`/`keydiff` 这类信号为什么差（@0.8 分别 −0.18 / −0.08）。

## 熵的细节

三者熵都接近（0.85–0.91），**说明"总量分布"看起来差不多，差别在 top-k 打在哪**——
LM 打在 sink，KVzip 打在 needle+部分 sink，K-as-Q 打在无关的后段。

## 对我们的意义

- 我们的 `PE_SCORE_MODE=context`（采样 prompt query + max）≈ **LM 那一行**，所以它在
  needle 类任务上会漏掉信息 token（needle rank 98）。
- 这解释了为什么 LongBench F1 上 context 够用（答案不依赖单点），但**在 retrieval/needle
  类高压缩比任务上，KVzip 式重建应该明显更好**——这一项我们还没测（TODO）。
- `expected`（ExpectedAttention）≈ 用 query 分布估计，也在 LM 这一族里，所以它没优势。
