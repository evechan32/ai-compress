# KV 压缩：当前结论（2026-09-17）

> 依据：本项目已提交的实验数据（`docs/kvpress-longbench.md`、`docs/attention-signal.md`、
> `docs/prompt-evict-vllm.md`、`docs/paper/chunkkv-eviction-vllm.md`）+ 2026-09-17 在 3090(sm_86)
> 上的惊讶度验证（`bench/probe_surprisal.py`、`bench/probe_surprisal_f1.py`）。
> **总 GPU 花费 ≈ 2–3 小时**（其余为装环境与探针）。

---

## 1. 机制层面：成立，但有 1 个未补的洞

**成立（有直接证据）**
- 零 fork vLLM 0.28 插件，块粒度 prompt KV 驱逐 + **真实物理释放**：
  可复现的 `prompt_nblk=120 → keep=10, freed=110`，pool 有界不增长。
- chunked prefill 支持；**TP>1 支持**（跨 rank all-reduce + `ModelRunnerOutput` 回传；
  TP=2 与 TP=1 结果逐项一致，7B 上均 15/15）。
- **FA2 静默隐患**：FA2 设了 R-SWA 元数据却不消费掩码，而 KV manager 仍释放块
  → 注意力读已释放显存，输出与基线逐字相同。已加启动护栏。

**未补的洞**
- **「物理释放」是推断的，不是证明的**：我们证明了"块被归还"与"输出在 TRITON 下不同"，
  没有证明"被释放的块再也不会被读到"。缺 **NaN 毒化实验**（FA2 的发现恰恰说明这条路径可能静默读已释放显存）。

## 2. 质量层面：我们的实现已在方法族前沿

| 配置 | ΔF1 vs 不驱逐 | n |
|---|---|---|
| 7B keep-50%（我们） | **−0.0030** | 300 |
| 7B keep-20%（我们） | **−0.0112** | 300 |
| kvpress @80% 最好的（snapkv） | −0.0121 | 100 |
| kvpress @50% 最好的（compactor） | +0.0036 | 100 |

**结论**：在 80% 驱逐档，我们的插件（−0.0112）**与外部最好的方法（−0.0121）同档**。
→ **该族的信号空间已基本耗尽**：compactor 族只在温和预算占优（@80% −0.04，最差一档）、
ada（头级预算）@50%/@80% 都不如 chunkkv、惊讶度刚被否决（见 §4）。

## 3. 收益层面：温和，且**动机与机制不匹配**（最重要的框架问题）

- 吞吐：keep-50% **1.12×**、keep-30% **1.26×**（容量受限、decode 为主）；prefill 为主时**零收益**。
- **峰值显存不降**：打分放在 prefill 完成后的第一个 decode 步 → 全量 prompt KV 已分配
  → **单请求长上下文仍会 OOM**。
  ⇒ 本方法实际是**并发/服务吞吐优化**，不是"长上下文可行性"方案。论文动机叙述需改写。

## 4. 已否决的路线（这些否证省下了后续钱）

| 路线 | 结论 | 证据 |
|---|---|---|
| **惊讶度**（零训练、~1.2× prefill） | ❌ **端到端无效** | 配对 bootstrap：vs random 池化 −0.026/−0.032（**不显著**）；@80% 删减 vs none **−0.050，显著为负**。token rank 好看(6–10)但**是弱代理** |
| 廉价复现"第二遍前向" | ❌ 全部失败 | 离线非因果 rank 15（真第二遍 6）、末位 query 60、K-as-Q 负相关；根因：第二遍改变**每一层** hidden（cos 0.77） |
| KVzip 的"复述指令" | ❌ 装饰性 | A(5)≈B(2)≈C(8)；起作用的是"带 cache 再跑一遍" |
| 低秩（早期 spike） | ❌ 已杀 | 权重近满秩；离线固定投影 1.6× → PPL ×1.30 |
| 换更好信号（compactor/cur/leverage/ada） | ❌ 无增量 | 温和预算不优于现有 chunkkv 式信号；激进预算更差 |

## 5. 可选路径（都还没做）

| # | 方向 | 成本 | 预期 |
|---|---|---|---|
| **1** | **把已有结果做扎实**：配对 CI、**NaN 毒化证明**、7B 吞吐、改写动机为"服务并发" | **≈0 新 GPU** | 一个诚实、可发表（偏 systems / 含负结果）的结论 |
| **2** | **换族：KV 卸载**（CPU/主机内存分层） | 中 | **零质量损失**；24G 显存 + 251G 主机内存天然两层；吞吐受 PCIe 约束 |
| **3** | **换族：KV 量化** | 中 | 2× 容量 / −0.04 F1（我们实测）；**可与我们叠加**；sm_86 无原生 FP8（需 sm_89+） |
| **4** | **换时序：prefill 内打分驱逐** | 高 | **唯一能降峰值的路径**（救单请求长上下文）；需要 query-agnostic 类信号 + 增量打分 |
| 5 | 免训练稀疏注意力（sm_86 解锁的 kernel） | 未知 | 从未查过，是换机器后才出现的选项 |

## 6. 一句话结论

**机制成立、但价值温和且定位被说错；该方法的信号空间已被我们走到尽头
（外部最好的方法与我们的实现同档，惊讶度等候选全部否决）；
进一步的数量级提升不能靠"换信号"，只能靠换族（卸载/量化）或换时序（prefill 内驱逐以降峰值）。**
